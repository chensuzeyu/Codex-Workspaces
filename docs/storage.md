# 聊天文件与运行状态

Codex 的具体文件布局可能随版本变化。先确认实际使用的 `CODEX_HOME`、各目录及符号链接的目标路径，再检查它们所在的文件系统。仅凭路径不能判断持久性和可恢复性。

| 内容 | 作用 | 拆分存储时的限制 |
|---|---|---|
| `sessions`、`archived_sessions` | 会话文件 | 可考虑放持久目录并从 HOME 建立链接；检查对象存储写入与上传完成语义 |
| `session_index.jsonl`、`history.jsonl` | 历史相关索引 | 不会因为会话目录迁移而自动持久化 |
| HOME 下的 `*.sqlite` 及 WAL | 数据库、状态与索引 | 应选择满足锁、共享内存、随机写及持久化要求的存储；不要把活跃数据库简单复制到对象存储 |
| 凭据、配置、程序、代理配置 | 运行与登录 | 聊天目录迁移不包含这些；各账号独立管理，避免泄露 |
| PID、锁、socket、缓存 | 进程运行时状态 | 可在实例本机重建，不是持久聊天文件 |

## 手动迁移原则

1. 先确认目标的容量、权限和持久性，以及软链接、写入、关闭和故障后上传语义；路径可见不等于远端数据已持久化。
2. 停止目标账号所有 Codex CLI/App Server 写入者，并阻止新进程启动；不要影响其他账号。活跃文件无法用简单复制保证一致。
3. 在独立目标目录复制两个聊天目录，逐文件比较数量、大小与哈希；检查原来索引引用的路径是否仍可通过链接访问。保留原目录以便回退，勿覆盖不明目标。
4. 在原 HOME 中用链接指向目标；任一步失败即恢复原目录，避免新旧目录分叉。重新启动后检查代表性历史读取、新会话写入和实际上传；同时验证两人代理仍正常。
5. 单独制定数据库及索引的持久化和恢复策略，并进行实例重建演练。任何周期同步都有间隔，且多个数据库与聊天文件不一定构成同一时间点的原子快照。

本工具不执行上述切换，也不自动启用备份；请依据环境安排中断窗口。会话文件通常含敏感信息，目标目录应仅授予必要人员访问。
